# Architecture Decision Records

## Purpose

This directory is the canonical record of durable architecture and engineering
workflow decisions. It implements the ADR policy in the Engineering
Constitution and SPEC-000.

## When to create an ADR

Create an ADR for a decision that materially affects architecture, repository
organization, engineering workflow, security, data, integrations, or
long-term maintainability. Do not create one for routine implementation detail.

## Conventions

- Use the template in [ADR-TEMPLATE.md](ADR-TEMPLATE.md).
- Name records sequentially as `ADR-0001-short-title.md`.
- Use one of: Proposed, Accepted, Superseded, Deprecated, or Rejected.
- Preserve superseded records and link the replacement.
- Link related tasks, pull requests, specifications, and ADRs.
